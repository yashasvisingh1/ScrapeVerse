# Bright Data Scraper Backend

This project provides a Go backend service for triggering a Bright Data Scraper Studio collector, polling until the job completes, downloading the dataset, writing results to CSV, and returning the result metadata plus CSV path to callers.

## What this project does

- accepts a scrape request from a client or CLI
- triggers a configured Bright Data Scraper Studio collector
- polls the dataset until completion
- retrieves collection results from the Bright Data API
- writes records to a CSV file with a backend-generated RFC3339 timestamp column
- returns JSON metadata and result data to the caller

## Architecture

The service is intentionally structured around a modular Go backend rather than a UI:

```text
client / CLI
    |
    v
HTTP POST /api/scrape
    |
    v
internal/handlers
    |
    v
internal/brightdata
    |   - trigger request
    |   - status polling
    |   - dataset retrieval
    |   - response parsing
    v
internal/csvwriter
    |
    v
output/*.csv
```

## Prerequisites

- Go 1.22 or newer
- A Bright Data account with a valid API token
- A Bright Data Scraper Studio collector ID

## Configuration

Copy the example env file and set actual values:

```bash
cp .env.example .env
```

Example values:

```env
BRIGHT_DATA_API_TOKEN=your_api_token_here
BRIGHT_DATA_COLLECTOR_ID=your_collector_id_here
BRIGHT_DATA_BASE_URL=https://api.brightdata.com
POLL_INTERVAL_SECONDS=5
POLL_TIMEOUT_SECONDS=300
OUTPUT_DIR=./output
```

Do not check in a real `.env` file. The project `.gitignore` excludes `.env` and `.env.*` except `.env.example`.

## How Bright Data is used

The backend calls Bright Data in the same shape as the documented Scraper Studio API:

```http
POST https://api.brightdata.com/dca/trigger?collector=COLLECTOR_ID&queue_next=1
Authorization: Bearer API_TOKEN
Content-Type: application/json

[]
```

The trigger response may include a collection ID under fields such as `id`, `collection_id`, or `job_id`. The code parses the JSON dynamically and fails clearly if no ID is found.

After triggering, the backend polls the dataset endpoint until the job is complete:

```http
GET https://api.brightdata.com/dca/dataset?id=COLLECTION_ID
Authorization: Bearer API_TOKEN
```

This is the mechanism used for completion detection because the Bright Data API returns status information or a completed dataset payload at that endpoint. The implementation accepts either a status field or a non-empty result array and treats the job as complete when the dataset is ready.

## Polling behavior

Polling uses a bounded loop:

- starts immediately after trigger
- checks `POLL_INTERVAL_SECONDS`
- stops after `POLL_TIMEOUT_SECONDS`
- returns a clear error if the job fails or times out
- respects Go context cancellation

The logic is not implemented as a busy-wait or an infinite loop.

## CSV output

CSV files are created under `OUTPUT_DIR` and names are generated using a filesystem-safe timestamp such as:

```text
output/scrape_2026-08-17T18-02-50+0500.csv
```

Each CSV row includes a timestamp generated by the backend itself:

```csv
timestamp,name,price,url
2026-08-17T18:02:50+05:30,Product A,$20,https://example.com/a
```

Nested objects or arrays are serialized as JSON inside the CSV cell.

## Run the backend

From the project root:

```bash
go mod download
export $(grep -v '^#' .env | xargs)
go run ./cmd/server
```

The server listens on the default Go HTTP server port and exposes:

```text
POST /api/scrape
```

## Trigger a scrape

Example:

```bash
curl -X POST http://localhost:8080/api/scrape \
  -H "Content-Type: application/json" \
  -d '{"query":"tops for women"}'
```

The `query` value is sent to the Scraper Studio collector as:

```json
[{ "query": "tops for women" }]
```

The collector's `InteractionCode.js` reads `input.query` and uses it to build the Amazon, Myntra, and Ajio search URLs. The legacy `url` request field is also accepted by the backend as an alias for `query`.

## Example API response

```json
{
  "success": true,
  "collection_id": "abc123",
  "timestamp": "2026-08-17T18:02:50+05:30",
  "records": 1,
  "csv_file": "output/scrape_2026-08-17T18-02-50+0500.csv",
  "data": [
    {
      "name": "Product A",
      "price": "$20",
      "url": "https://example.com/a"
    }
  ]
}
```

## Notes

- The code isolates Bright Data-specific HTTP logic under `internal/brightdata`.
- The request body accepts `query`; `url` remains a compatibility alias. The collector receives the value as `input.query`.
- API tokens are never returned in any response and are never logged.
